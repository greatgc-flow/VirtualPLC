# 재귀적 MECE: 수트 → 영역 → 파티션 → 사례 → 오라클

## 1. 무중복의 정의
각 사례는 **primary_domain 하나**를 소유한다. domain, wire, transport, end_to_end, security, performance, platform, governance, scenario. 다른 분류(단계, 정상성, 입력 유형, 실패 효과, 리스크, 테스트 계층)는 직교 보조 축이다. 예를 들어 하나의 오류 프레임이 FR-007과 SEC-002 모두에 링크되어도 요구의 교차검증이지 중복 사례가 아니다.

**귀속 우선순위**: (1) 최초 불변식이 깨지는 계층을 소유자, (2) 인접 층은 교차 리스크 레퍼런스, (3) 동일 입력과 oracle과 실행 층이 모두 같으면 합병 후보, (4) 기존 TC-ID는 삭제하지 않고 origin ID로 추적.

## 2. 완전성의 정의(선언한 P0 내부에서만)
- 기준 요구 37 = P0 34 + 미래 3 (FR-016/017/018). 선언하지 않은 PLC 기능의 일반적 완결성을 주장하지 않는다.
- 기본 69건 전부 **고유 CASE**로 1:1 인계.
- 각 P0 요구 ≥2 사례, 모든 P0 요구에 적어도 1 시나리오/오라클, 등록된 15 리스크 중 고아 리스크 0.
- 정상/경계/해석가능한 오류/프레이밍 치명오류/단절/병렬/회복/과부하/보안/운영/변경관리의 실패 모드를 나눈다.
- P1/P2 변경은 `G5` 없이 P0로 편입하지 않는다.

## 3. 단계별 파티션 + 간극(정직한 상태)
| 단계 | 원인 | 판정 | 현재 구현 상태 |
|--|--|--|--|
| 설계 정합성 | 링크, 지원 행렬, 증거 등급 | 정적 자동·변이검사 | 실행 가능 |
| 순수 도메인 | 메모리/원자성/설정/검증 | 독립 포트 기반 TDD | 도메인 포트 스켈레톤 제공, 구현 필요 |
| Wire | 3E frame/byte/nibble/error | 골든 byte와 연결 검사 | 참조 인코더·실서버 45케이스 연결됨 |
| 전송/통합 | TCP segment/merge/EOF/FIFO/race | 실제 별도 프로세스 | 실서버 기동 전 미실행 |
| 클라이언트 호환 | 고정 pymcprotocol 버전 | pinned roundtrip+request capture | pinned 버전·캡처 미완료 |
| 견고성/보안 | timeout/fuzz/log/자원 제한 | 공격 입력+무변경+상한 | 여러 사례 오라클 설계, 실행 일부 미연결 |
| 운영/플랫폼 | Windows/Linux, CI, 복구, 지표 | 증거·릴리즈 게이트 | 별도 CI/운영 실측 필요 |
| 확장 | 4E/ASCII/고장주입 | 별도 ADR/테스트 | P1/P2 의도적 제외 |

## 4. 종(생애주기) × 횡(책임계층)
`source → requirement → acceptance → owner → CASE → runner/adapter → JUnit/trace → risk/gate → incident → regression CASE`의 유향 추적 그래프를 단일 JSONL로 유지. `validate_suite.py`가 정본 요구/리스크/원본 TC와 신규 CASE를 상호 검사. 거짓 실행증거(`PASS`만 임의 변경)는 의도적으로 거절한다.

## 5. 탐색 누락 방지
제품 모델·장치 코드·주소 radix, 응답코드, cmd cap, 프로토콜 프레임 버전, client 라이브러리 버전이 바뀌면 `G0-F/E/C`부터 다시 열린다. 테스트 카탈로그만 고쳐서 서버 호환성 보증으로 표시할 수 없다.
