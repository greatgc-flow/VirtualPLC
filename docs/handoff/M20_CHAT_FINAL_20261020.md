## 3. 최신 테스트 증거와 판정 해석
- M20에서 완료된 JUnit 10개를 검증해 pytest **546건 PASS**, unittest 추가 하위 테스트 **5건 PASS**, loopback live TCP **45/45 PASS**. 고유 pytest node ID 중복 0, 고유 CASE-ID 중복 0.
- M20 이번 JUnit에 실제로 관측된 P0는 **160개 고유 CASE-ID**이다. 과거 별도 세트에서 관측된 누적 **183/199**는 역사적 로컬 증거이고 이번 회귀와 같지 않으며, 독립 승인/제조사 인증/릴리즈 PASS가 아니다.
- 외부 P0 **16건 미검증**, 신규 외부 P0 승인 **0건**, 최종 release **HOLD**. 미실행·SKIP·모의/정적 검사·성공 주장만으로 PASS 승격 금지.
- `M20_RUN_SUMMARY.json`에 10개 JUnit 파일별 해시, 검사 수, 플랫폼(Python 3.13.5 Linux)이 있음.
- M20에서 처음 실패한 M7 모의 서버 호환성 테스트는 선택 필드 부재를 허용하도록 수정하고 재실행함. 최초 실패 XML을 별도로 보존하지 못한 증적 보존 결함을 M21에서 재발 방지해야 함.
- 제한시간으로 중단된 원래 TCP 일괄 실행은 집계하지 않았고, 후속 4개 소그룹을 재실행해 45건을 완료함.

## 4. 구현 상태: BL-INT-001 완료
- `virtual_plc/faults.py`: 기본 비활성(`None`) 결정적 옵션 `FaultPlan`. 작업 `pass`, `delay`(1~500ms), `disconnect`; 최대 256개 스텝; 순서·원자성 관리.
- `virtual_plc/server.py`: 유효·경로 수용된 3E 프레임 이후, D/M 메모리 작업 이전에 FaultPlan 적용. disconnect 시 D/M 불변성; 옵션 누락인 기존 mock과 하위 호환.
- `virtual_plc/telemetry.py`: 페이로드·IP·레지스터 값을 기록하지 않고 통계만 수집.
- TCP loopback `127.0.0.1`만 허용. 실제 PLC에 대한 연결·중계 기능 없음. CLI/TOML에 장애 주입 키를 노출하지 않음.
- 다중 클라이언트에서 계획 소비 순서는 프레임 완료/락 스케줄링 기준이며 클라이언트별 시간순 보장은 없다.

## 5. 외부 의존성 백로그 16건 — 계속 HOLD, 내부 개발 비차단
- **BL-EXT-CLIENT / G0-C / 6건**: CASE-0027,0028,0029,0109,0110,0111. SHA 인증된 실제 `pymcprotocol==0.3.0` wheel과 Windows 클린 체크아웃 실행 JUnit·원본 6 요청 패킷·환경 증거 확보 시 재개.
- **BL-EXT-VENDOR / G0-E / 6건**: CASE-0018,0019,0020,0064,0088,0090. 정확한 Mitsubishi CPU/모듈/펌웨어/공식 매뉴얼·판본·페이지 확인 시 재개. `0xC059`를 제조사 확정값으로 간주하지 않음.
- **BL-EXT-WINDOWS / G3 / 2건**: CASE-0044,0128. 실제 native Windows >= 3.11 실행·출처 증적이 접수되면 재개.
- **BL-EXT-REVIEW / G4 / 2건**: CASE-0055,0147. 독립 검토자·라이선스·failback·생산망 미접속·필수 원본 검증 완료 시 재개.
- 담당 역할·증거·acceptance·resume_when의 최종 정본은 `backlog/M20_BACKLOG.json`. 관련 자료가 없는 한 위 항목 반복 요청/차단 금지.
